# WebAssembly spec runtime cases

The eight scalar scripts come from [WebAssembly spec core tests](https://github.com/WebAssembly/spec/tree/608711107b7f1edb13efd57b7d79b49477462d36/test/core). The `simd_*.wast` scripts come from [core SIMD tests](https://github.com/WebAssembly/spec/tree/608711107b7f1edb13efd57b7d79b49477462d36/test/core/simd). The six relaxed SIMD scripts come from [core relaxed SIMD tests](https://github.com/WebAssembly/spec/tree/608711107b7f1edb13efd57b7d79b49477462d36/test/core/relaxed-simd). All are pinned at commit `608711107b7f1edb13efd57b7d79b49477462d36` and covered by
[`licenses/WebAssembly-spec-Apache-2.0.txt`](../../licenses/WebAssembly-spec-Apache-2.0.txt).

The added `const.wast`, `return_call*.wast`, `multi_memory_*.wast`, and `memory64_*.wast` files come from the same pinned core test tree. `extended_const_elements.wast` contains exact lines 1055–1110 of that tree's `elem.wast`. The runtime harness supplies a pure Wasm `spectest` provider for the print function and immutable global used by the added scripts.

`spec_runtime.rs` checks return and trap assertions, malformed and invalid module rejection, exact float bits, NaN patterns, and allowed alternatives for relaxed SIMD. Validation cases assert rejection without matching diagnostic text. The tail-call scripts now include their public null function-reference assertions. No assertions are skipped in the included scripts.

Each invocation gets fresh state by default. For `ref_func.wast` and `select_functions.wast`, the harness replays preceding successful actions in a generated Wasm wrapper within one lane. It supports scalar arguments, null function arguments, numeric or untyped function results, and state mutations; it does not replay state changes from trapped or exceptional actions. Other scripts with assertions that depend on state persisting across separate invocations remain outside this harness. Some 64-bit table scripts require `externref`, which is outside the current `funcref` table target. `simd_align.wast` and `simd_const.wast` require persistent state and remain excluded. `simd_linking.wast` and `simd_memory-multi.wast` contain no runtime assertions for this harness. Library tests compare the supported stateful operations and imports with fresh Wasmtime instances.

`br_on_null.wast`, `br_on_non_null.wast`, `call_ref.wast`, `ref_as_non_null.wast`, `ref_func.wast`, `return_call_ref.wast`, and `type-equivalence.wast` come unchanged from the pinned core tree. `type_rec_functions.wast` contains exact lines 1–36 and 45–66 of `type-rec.wast`; the remaining sections combine function types with unsupported GC object types. `exceptions_{tag,throw,throw_ref,try_table}.wast` come unchanged from `test/core/exceptions/` at the same commit. The harness checks tag linking, `assert_unlinkable`, and `assert_exception`, including imported tag aliases. It reserves 256 call frames for runtime scripts so the ordinary recursion cases can finish; production defaults remain 32. `local_init.wast` uses public non-nullable external references and `ref_null.wast` combines GC and public external or exception references; these scripts remain excluded. Focused library integration tests cover non-defaultable function locals, function subtyping, recursive group identity, vector exception payloads, retained exception references, loop handlers, provider initialization, and resource limits against Wasmtime or explicit expected errors.

`select_functions.wast` contains the pinned `select.wast` with only lines 252, 258, and 259 removed. Those three assertions use unsupported public external references. All numeric and function-reference runtime assertions and all validation assertions run.
